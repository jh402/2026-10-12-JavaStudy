# 10. 예외처리
프로그램 실행 중 발생하는 문제를 감지하고 적절하게 처리하여 프로그램이 갑자기 종료되지 않도록 하는 기능

## 10.1. 목적
- 프로그램의 비정상 종료 방지
- 오류 상황을 사용자에게 안내
- 오류 원인 파악 및 디버깅 도움
- 정상적인 프로그램 흐름 유지
- 자원(파일, DB 등) 관리

## 10.2. 예외처리 계층구조
```
                  Object
                     |
                Throwable : 예외처리의 최상위 클래스
     ┌───────────────┴─────────────┐
   Error                       Exception
               ┌───────────────────┴────────────────────┐ 
      CheckedException : 컴파일 시 에러          UnCheckedException : 실행 시 에러
               |                                        |
         IOException 등등                       RuntimeException : 필요에 의해서만 예외처리
                                                        |
                                         ArrayIndexOutOfBoundsException 등등
```
### 10.2.1. Throwable
||Error(에러)|Exception(예외)|
|---|---|---|
|의미|JVM 또는 시스템의 심각한 문제(시스템 붕괴)|프로그램에서 처리할 수 있는 예외 상황|
|처리|프로그램 내부에서 복구 불가|개발자가 로직으로 대응 및 처리 가능|
|대표 예시|OutOfMemoryError, StackOverflowError|IOException, SQLException|
### 10.2.2. Exception
||CheckedException|UnCheckedException|
|---|---|---|
|예외 발생|컴파일 시점 검사|실행 시점 기습 발생|
|예외 처리|예외 처리를 컴파일러가 강제함|컴파일러가 처리를 강제하지 않음(개발자 책임)|
|계열|RuntimeException 제외한 Exception계열|RuntimeException계열|

### 10.2.3. **CheckedException** 하위 클래스
- IOException : 입출력 관련
  - 메모리 입출력(System.in/System.out)
  - 파일 입출력(FileReader/FileWriter/FileInputStream/FileOutputStream)
  - 네트워크 입출력(BufferedReader/OutputStream)
- InterruptedException
  - 쓰레드 충돌 방지(비동기)
- MalformedURLException
  - URL-크롤링
- ClassNotFoundException
  - 리플렉션(클래스명을 이용해서 제어)
- SQLException
  - DB연동

### 10.2.4. **RuntimeException** 하위 클래스
- ArrayIndexOutOfBoundsException : 배열 범위 초과
- NumberFormatException : 문자열을 숫자 변경이 안되는 경우
- ClassCastException : 클래스 형 변환
- NullPointerException : 메모리 할당없이 사용
- ArithmeticException : 0으로 나눈 경우

## 10.3. try-catch
- 직접 처리
- 예외 복구

### 10.3.1. 기본 문법
```java
try{
  //예외가 발생할 수 있는 코드
  //예외가 발생하면 catch로 이동
}catch(Exception e  /*예외클래스 변수명*/){
  //예외가 발생했을 때 처리
}finally{
  //마지막 정리 작업
}
```

### 10.3.2. 다중처리
```java
try{
  //예외가 발생할 수 있는 코드
}catch(NumberFormatException e){
  //문자열이 정수로 변환이 안될 때 실행
}catch(ArrayIndexOutOfBoundsException e){
  //배열 범위 밖일 때
}catch(Exception e){
  //기타 등등
  //Exception은 위의 두 클래스보다 상위 클래스
}
```
- 여러 개의 `catch` 사용
- 상위 클래스는 하위 클래스보다 나중에 사용

### 10.3.3. try-with-resources
```java
try(FileReader reader=new FileReader("test.txt")){//블록 종료 시 자동으로 close() 호출
  int data=reader.read();
}catch(IOException e){
  System.out.println("파일 처리 오류");
}
```
- Java 7+ 이상 지원
- 객체가 반드시 AutoCloseable 인터페이스를 구현해야 작동
- 다중 리소스 선언 시 세미콜론`;`으로 구분
- 가장 나중에 선언된 자원부터 역순으로 안전하게 닫힘

## 10.4. throws
- 간접 처리
- 예외 회피
- 메소드를 호출한 곳으로 예외를 떠넘김
- `throws` 키워드가 붙어 있는 메소드를 호출한 곳에서 예외를 처리해야 함
```java
//메소드명 뒤에 throws 예외처리클래스명
public void method() throws IOException, SQLException{
  //...
}
```
- `,`를 사용하여 여러 개 선언 가능

## 10.5. 사용자정의
- 필요한 상황에 맞는 예외 클래스를 직접 생성
- Exception 또는 RuntimeException 상속 후 생성자 정의

**예외 클래스 직접 생성**
```java
class MyCustomException extends Exception{
  public MyCustomException(String msg){
    super(msg);
  }
}
```
- 예외 객체의 공통 메소드 `getMessage()`의 리턴값으로 사용하기 위해 부모 생성자 매개값으로 넘겨줌

## 10.6. throw
- 특정 조건에서 예외를 강제로 발생시킬 때 사용
- 주로 사용자정의 예외나 논리적오류
```java
if(조건){
  throw new MyCustomException("잘못된 값입니다.");
}
```

## 10.7. 예외처리 메소드
`getMessage()` : 에러 메세지를 보여줌<br>
`printStackTrace()` : 에러 위치를 확인


## 10.8. 예외처리 순서
1. if문 고려
2. try~catch문으로 에러 처리
3. 복잡한 소스나 이미 만들어 놓은 경우에 `throws`java 사용
4. 테스트할 때 `throw` 사용
