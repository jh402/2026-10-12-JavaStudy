# 10. 예외처리
프로그램 실행 중 발생하는 문제를 감지하고 적절하게 처리하여 프로그램이 갑자기 종료되지 않도록 하는 기능

## 10.1. 목적
- 프로그램의 비정상 종료 방지
- 오류 상황을 사용자에게 안내
- 오류 원인 파악 및 디버깅 도움
- 정상적인 프로그램 흐름 유지
- 자원(파일, DB 등) 관리

## 10.2. 예외처리 계층구조
```
               Object
                 |
            Throwable : 예외처리의 최상위 클래스
     ┌───────────┴───────────┐
   Error                 Exception
               ┌─────────────┴──────────────┐ 
          CheckedException          UnCheckedException
               |                            |
         IOException 등등             RuntimeException : 필요에 의해서만 예외처리
                                            |
                              ArrayIndexOutOfBoundsException 등등
```
**CheckedException** 하위 클래스
- IOException : 입출력 관련
  - 메모리 입출력(System.in/System.out)
  - 파일 입출력(FileReader/FileWriter/FileInputStream/FileOutputStream)
  - 네트워크 입출력(BufferedReader/OutputStream)
- InterruptedException
  - 쓰레드 충돌 방지(비동기)
- MalformedURLException
  - URL-크롤링
- ClassNotFoundException
  - 리플렉션(클래스명을 이용해서 제어)
- SQLException
  - DB연동

**RuntimeException** 하위 클래스
- ArrayIndexOutOfBoundsException : 배열 범위 초과
- NumberFormatException : 문자열을 숫자 변경이 안되는 경우
- ClassCastException : 클래스 형 변환
- NullPointerException : 메모리 할당없이 사용
- ArithmeticException : 0으로 나눈 경우

## 10.3. try-catch
### 10.3.1. 기본 문법
```java
try{
  //예외가 발생할 수 있는 코드
  //예외가 발생하면 catch로 이동
}catch(Exception e  /*예외클래스 변수명*/){
  //예외가 발생했을 때 처리
}finally{
  //마지막 정리 작업
}
```
### 10.3.2. 다중처리
```java
try{
  //예외가 발생할 수 있는 코드
}catch(NumberFormatException e){
  //문자열이 정수로 변환이 안될 때 실행
}catch(ArrayIndexOutOfBoundsException e){
  //배열 범위 밖일 때
}catch(Exception e){
  //기타 등등
  //Exception은 위의 두 클래스보다 상위 클래스
}
```
- 여러 개의 `catch` 사용
- 상위 클래스는 하위 클래스보다 나중에 사용
