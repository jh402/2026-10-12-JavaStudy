# 7. 클래스
## 7.1. 클래스란?
- 객체를 만들기 위한 설계도
- 데이터와 기능을 정의하여 같은 형태의 여러 객체를 생성

## 7.2. 구성요소
### 7.2.1. 필드
- 객체가 가지는 데이터와 상태
- 인스턴스 변수, 정적 변수, 상수 등
```java
public class Student{
  //필드
  private String name; //인스턴스 변수
  private int age; //인스턴스 변수
  private static int count; //정적 변수
  public static final String SCHOOL="IT학교"; //상수
  //생성자
  public Student(String name, ing age){
    this.name=name;
    this.age=age;
    count++;
  }
  //메소드
  public void introduce(){
    System.out.println("이름: "+name+", 나이: "+age);
  }
}
```
### 7.2.2. 생성자
- 객체 생성 시 초기화
- 클래스 이름과 동일, 반환형 없음
```java
class Student{
  String name;
  int age;
  //생성자
  Student(String name, int age){
    this.name=name;
    this.age=age;
  }
}
```
#### 7.2.2.1. 기본 생성자
클래스에 생성자 선언이 없으면 컴파일러는 기본 생성자를 바이트코드 파일에 자동으로 추가

**소스 파일(Car.java)**
```java
public class Car{

}
```

**바이트코드 파일(Car.class)**
```java
public class Car{
  public Car() {} //자동 추가
}
```
### 7.2.3. 메소드
- 객체의 기능과 동작 정의
- 반환형, 매개변수 사용 가능

### 7.2.4. 접근 제어자
- public, protected, default, private
- 접근 범위 제한

### 7.2.5. 정적 멤버(static)
- 클래스에 소속, 객체 없이 사용
- 정적 변수, 정적 메소드

### 7.2.6. 상수(final)
- 값을 변경할 수 없는 변수
- 주로 대문자와 함께 사용

## 7.3. 변수의 종류
|구분|지역 변수|인스턴스 변수|정적 변수|
|---|---|---|---|
|선언 위치|메소드/블록 내부|클래스 내부(메소드 외부)|클래스 내부(변수명 앞에 static)|
|소속|메소드/블록|객체|클래스|
|저장 방식|스택 영역|힙 영역(객체마다 별도)|메소드 영역(클래스당 하나)|
|접근 범위|선언된 블록 내|객체 내|클래스 전체|
|초기화|직접 초기화 필요|기본값 또는 생성자|명시적 초기화|

## 7.4. 초기화 블록
복잡한 초기화에 사용
```java
class Student{
  //인스턴스 필드
  String name;
  int age;
  //정적 필드
	static int count=0;
  //인스턴스 초기화 블록
  { age=20;}
  //정적 초기화 블록
	static { count=1; }
  //생성자
  Student(String name){
    this.name=name;
  }
}
```
### 7.4.1. 인스턴스 초기화 블록
`{}`: 객체가 생성될 때마다 실행

**초기화 순서**
1. 기본값
2. 명시적 초기화
3. 초기화 블록
4. 생성자

### 7.4.2. 스태틱 초기화 블록
`static {}`: 클래스 로딩 될 때 호출되며 각 클래스당 최초 1회만 실행

**초기화 순서**
1. 기본값
2. 명시적 초기화
3. 초기화 블록

## 7.5. this와 super
### 7.5.1. this(현재 객체 참조)
- 현재 객체와 필드/메소드 참조
- 매개변수와 필드 구분할 때 사용
```java
this.name=name;
```

**this()**
- 같은 클래스의 다른 생성자 호출
- 생성자의 첫 번째 문장에 위치
- 초기화 코드 중복 제거
```java
this("이름", 18);
```

### 7.5.2. super(부모 클래스 참조)
- 부모 클래스의 필드에 접근 시 사용
- 부모 클래스의 메소드에 접근 시 사용

**super()**
- 부모 클래스의 생성자 호출
- 생성자의 첫 번째 문장에 위치
```java
super(name);
```

## 7.6. 객체지향 프로그래밍
### 7.6.1. 객체란?
- 물리적으로 존재하거나 개념적인 것 중에서 다른 것과  식별 가능한 것
- 예: 자동차, 자전거, 책 등

### 7.6.2. 객체지향 프로그래밍의 특징
#### 7.6.2.1. 캡슐화
- 객체의 데이터(필드), 동작(메소드)을 하나로 묶고 실제 구현 내용을 외부에 감추는 것
- 접근 제한자 사용

#### 7.5.2.2. 상속
- 부모 객체가 가지고 있는 필드와 메소드를 자식 객체에게 물려주는 것
- 코드의 재사용성을 높여줌
- 유지 보수 시간을 최소화

#### 7.5.2.3. 다형성
- 사용 방법은 동일하지만 실행 결과가 다양하게 나오는 성질
- 오버로딩, 오버라이딩

## 7.7. 패키지
- 패키지는 클래스의 일부분으로 클래스를 식별하는 용도로 사용
- 개발 회사 도메인 이름의 역순으로 만든다
- 상위 패키지와 하위 패키지를 도트(.)로 구분

### 7.7.1. 선언
- 컴파일러는 클래스의 패키지 선언을 보고 디렉토리를 자동 생성
- 항상 소스 파일 최상단에 위치
- 패키지 이름은 모두 소문자로 작성하는 것이 관례
- 패키지 이름이 중복되지 않도록 회사 도메인 이름의 역순으로 작성 후 마지막에는 프로젝트 이름을 붙여주는 것이 일반적
```java
package 상위패키지.하위패키지;
```

## 7.8. 접근 제한자
- 중요한 필드와 메소드가 외부로 노출되지 않도록 해 객체의 무결성을 유지하기 위해 사용
- default는 생략 가능

|접근 제한자|제한 대상|제한 범위|
|---|---|---|
|public|클래스, 필드, 생성자, 메소드|모든 패키지에서 사용 가능|
|protected|필드, 생성자, 메소드|같은 패키지나 자식 객체만 사용 가능|
|default|클래스, 필드, 생성자, 메소드|같은 패키지|
|private|필드, 생성자, 메소드|객체 내부|

## 7.9. DTO와 VO
실무에서 '데이터를 어떻게 다룰 것인가' 에 따라 배송 수단(DTO)과 불변의 값(VO)이라는 두 가지 패턴으로 나뉨
### 7.7.1. DTO
- 목적
  - 서로 다른 계층 간에 데이터를 전달하기 위한 순수 운반체
  - 예: MemberDTO, BoardDTO
- 특징
  - 복잡한 비즈니스 로직을 포함하지 않음
  - 데이터를 담고 꺼내는 것에 집중
- 가변성
  - 필요에 따라 데이터를 유연하게 담아야 하므로 보통 Getter와 Setter를 모두 가짐
### 7.7.2. VO
- 목적
  - 값 자체를 물리적으로 표현하는 객체
- 불변성
  - 생성 시 단 한 번만 값을 세팅하며 이후 변경 불가능
  - final 필드 사용
  - Setter 제공 안함
- 유효성 내장
  - 생성자 내부에서 규칙을 스스로 검증
  - 항상 '안전한 값' 임을 증명

### 7.7.3. DTO vs VO
||DTO|VO|
|---|---|---|
|핵심 목적|계층 간 데이터 전달(운반체)|고유한 값 자체를 표현(개념)|
|가변성|보통 변경 가능(Setter 보유 O)|완전한 불변 객체(Setter X)|
|로직 및 검증|순수 데이터만 보관|생성 시 자체 유효성 검증 규칙 포함|
|동등성 비교|특별한 비교 규칙 없음|equals() / hashCode()를 통한 값 비교 필수|
|대표 예시|PaymentDTO, BoardDTO|MoneyVO, PointVO|

## 7.10. 상속
- 자바에서는 extends를 이용해서 상속
- 부모클래스의
### 7.10.1. 형태
[접근제한자] class 자식클래스 extends 부모클래스
```java
//부모클래스
class Animal{
  String name;
  void sound(){
    System.out.println("동물 소리");
  }
}
//자식클래스
class Dog extends Animal{
  String type;
}
```

### 7.10.2. 생성자 실행 순서
1. 객체 메모리 할당 및 기본값 초기화
2. 부모 클래스의 필드 초기화식, 초기화 블록 실행
3. 부모 클래스 생성자 실행
4. 자식 클래스의 필드 초기화식, 초기화 블록 실행
5. 자식 클래스 생성자 실행

부모 생성자가 먼저 실행되는 이유 : 부모의 부분이 먼저 초기화 되어야 자식 객체가 정상적으로 생성

### 7.11. 다형성
- 부모 타입의 참조 변수로 자식 객체를 참조
- 실제 객체의 타입에 따라 메소드가 실행
#### 7.11.1. 오버라이딩
- 부모의 메소드를 자식이 재정의
- 실제 객체 타입에 따라 실행
- 메소드 시그니처(이름, 매개변수, 반환타입)가 동일해야 함
```java
//부모클래스
class Animal{
  String name;
  void sound(){
    System.out.println("동물 소리");
  }
}
//자식클래스
class Dog extends Animal{
  String type;
  System.out.println("멍멍");
}
```
#### 7.11.2. 오버로딩
- 같은 클래스 내에서 같은 이름의 메소드 여러 개
- 매개변수의 개수/타입/순서가 다름
```java
void bark(){...}
void bark(String type){...}
void bark(int count){...}
```

**생성자 오버로딩**
```java
class A{
  int a, b, c;
  A(){...}
  A(int a){...}
  A(int a, int b, int c){...}
}
```
